## Piece 1 — Soft-to-hard clamp derivation and the four-task table

**Type:** derivation · **Time:** ~45 min

**Learning goals**
- Derive the settled value of a node under a soft clamp at finite precision π.
- Show algebraically that π→∞ reproduces the hard-clamp value, i.e. that hard clamping is a limiting case of the same energy-minimization equation, not a separate mechanism.
- Explain, in terms of residual local error, why the clamped node's own error term does *not* blow up as π→∞ even though π does.
- Reconstruct the four-task clamp table (classification / generation / reconstruction / goal-directed) from the fixed-vs-free principle, not from memory.

**Task**

Part A (algebra). A node `x` receives one top-down prediction `μ` with precision `π_pred`, and is softly clamped toward a target `x_clamp` with precision `π`. Its energy is:

```
E(x) = π_pred · (x − μ)² + π · (x − x_clamp)²
```

1. Minimize `E` with respect to `x` (set `dE/dx = 0`) and solve for the settled value `x*` as a function of `π_pred`, `μ`, `π`, `x_clamp`.
2. Using `π_pred = 1`, `μ = 3`, `x_clamp = 7`, tabulate `x*` for `π ∈ {0, 1, 3, 9, 99}` and the limit `π → ∞`.
3. For each row, also compute the two energy *terms* separately: the prediction-error term `π_pred·(x*−μ)²` and the clamp term `π·(x*−x_clamp)²`. Describe what happens to each term as `π → ∞` — in particular, does the prediction-error term diverge? Does the clamp term?
4. State in one sentence why this makes "hard clamp" a special case of "soft clamp at π→∞" rather than a different piece of machinery.

Part B (table). Using only the fixed-vs-free principle ("clamped nodes are boundary conditions; free nodes minimize local error; the answer is whichever free node you read out after settling"), fill in this table without looking anything up first, then check against C4's per-task patterns:

| Task | Fixed (clamped) | Free (settles) | Read out after settling |
|---|---|---|---|
| Classification | | | |
| Generation | | | |
| Reconstruction (half an MNIST digit given) | | | |
| Goal-directed action | | | |

For the reconstruction row specifically: name exactly which pixels are clamped and which are free, and contrast this with the generation row — both involve an image node, but the clamp is on a different subset (label vs. a known half of the pixels).

**Deliverable:** handwritten or typed derivation (Part A, steps 1–4) plus the completed table (Part B), as a single page or two.

**Rubric**

| Band | Criteria |
|---|---|
| Strong | Correct closed-form `x*`, correct numeric table matching the arithmetic below to within rounding, correctly identifies that the clamp-term goes to 0 and the prediction-error term saturates at `(x_clamp−μ)²` rather than diverging, states the π→∞ limit as "same equation, one term dominates completely" rather than "a new rule for clamped nodes." Table filled correctly on the first attempt with reconstruction correctly contrasted against generation (different subset of the image node clamped, not a different node).       |
| Adequate | Correct `x*` formula and mostly correct numbers (minor arithmetic slips), gets the qualitative limit right (x*→x_clamp) but is vague on why the residual error doesn't diverge. Table correct after being told to re-derive one or two cells rather than being given the answer.               |
| Not yet | Cannot set up `dE/dx=0`, or treats the hard clamp as an unrelated special rule ("clamped nodes just don't have an energy term"), or the table conflates generation and reconstruction (clamps the whole image in both).            |

**Grader key** (teacher AI only)

Part A:
- `x* = (π_pred·μ + π·x_clamp) / (π_pred + π)`
- Table (π_pred=1, μ=3, x_clamp=7):

  | π | x* | pred-error term `(x*−μ)²` | clamp term `π(x*−x_clamp)²` | total E |
  |---|---|---|---|---|
  | 0 | 3.00 | 0.00 | 0.00 | 0.00 |
  | 1 | 5.00 | 4.00 | 4.00 | 8.00 |
  | 3 | 6.00 | 9.00 | 3.00 | 12.00 |
  | 9 | 6.60 | 12.96 | 1.44 | 14.40 |
  | 99 | 6.96 | 15.68 | 0.16 | 15.84 |
  | ∞ | 7.00 | 16.00 | 0.00 | 16.00 |

- The prediction-error term rises monotonically but **saturates** at `(x_clamp−μ)² = 16`; it never diverges because `x*` itself converges to the finite value `x_clamp`. The clamp term falls to exactly 0 in the limit because `(x*−x_clamp)→0` faster than `π→∞` blows it up (the product is a well-defined limit of a rational function, not a `0·∞` indeterminate once you substitute the closed form). Total energy converges to 16 — a *finite* residual, permanently parked on the node's own prediction-error term. This residual is exactly what would show up as elevated local error / stress at the clamped node in the project's vocabulary — clamping doesn't erase disagreement, it relocates who has to resolve it.
- One-sentence answer for step 4: hard clamping is `x*` at the π→∞ limit of the *same* stationary-point equation used for every other node; nothing new is introduced, one term's coefficient is simply sent to infinity so it alone determines `x*`.

Part B (reference table):

| Task | Fixed (clamped) | Free (settles) | Read out |
|---|---|---|---|
| Classification | Image/observation nodes (hard) | Label node, hidden/latent nodes | Label node |
| Generation | Label node (hard) | Image nodes, hidden/latent nodes | Image nodes |
| Reconstruction | The known half of the image's pixels (hard) | The missing half of the pixels, latent nodes, (label optional) | The missing pixels |
| Goal-directed action | Current sensor state (hard); desired next state (soft) | Action node; next-state node (still settles even though soft-clamped) | Action node |

Reconstruction vs. generation: both clamp part of the "image side," but generation clamps the *label* and frees the *entire* image, while reconstruction clamps a *known subset of pixels* and frees the *remaining subset* — the label is not what's fixed, and the image is only partially free.

**Teacher constraints**
- Hint 1: "Write the stationary condition `dE/dx=0` explicitly before trying to guess the answer."
- Hint 2: "Plug in the five π values one at a time rather than trying to see the pattern first — the pattern falls out of the numbers."
- Hint 3: "For the table, ask for each row: which node's value is given from the outside, and which node's value do you read as 'the answer'? If two rows have the same fixed node, you've mismatched something."
- Never: supply the closed-form `x*` before the learner has attempted the derivative themselves at least once. Never fill in a single table cell for them — point at the fixed-vs-free principle and ask them to re-derive it.

## Piece 2 — One PC network, four clamp configurations (+ one failure)

**Type:** simulation · **Time:** ~90 min

**Learning goals**
- Implement clamping as a boundary condition on gradient-descent settling, not as a special-cased input.
- Observe, numerically, that classification, generation, and reconstruction are the *same* settling loop with different fixed/free node assignments.
- Implement the CartPole-style goal-directed pattern (hard-clamp current state, soft-clamp desired next state, free action) on a small synthetic dynamics model, and read the settled action off.
- Produce, in code, an over-constrained clamp and observe energy plateauing above zero instead of settling — the empirical counterpart of Piece 1's residual-error result.

**Task**

Write a single self-contained Python script (numpy or PyTorch, no external data, under ~100 lines) with:

1. A small generative subgraph `L → Z → X`: label node (dim 3, one-hot), latent node (dim 4), observation node (dim 6). Give it some fixed weights or a short pretraining loop so that each label deterministically generates a distinguishable pattern in `X`. Write one generic "settle" function that takes an energy, a set of free node names, and does gradient descent on only those nodes for N steps, leaving clamped nodes untouched.
2. Run it under three configs, using the *same* settle function each time, only changing which nodes are in `free`:
   - **Classification** — clamp `X` to a (possibly noisy) observation, free `L, Z`. Read off `argmax(L)` at the end.
   - **Generation** — clamp `L` to a one-hot label, free `Z, X`. Read off `X` at the end and compare it to the class's expected pattern.
   - **Reconstruction** — clamp *half* of `X`'s dimensions to a corrupted/partial observation, free the other half of `X` (and `Z`, and optionally `L`). Read off the completed `X`.
3. A second small subgraph for goal-directed action: state node `S` (dim 2, e.g. position/velocity), action node `A` (dim 1), predicted-next-state node `S'` (dim 2), with some simple dynamics prediction `S'_pred = f(S, A)`. Run one config: hard-clamp `S` to a "current sensor reading," **soft-clamp** `S'` toward a desired goal state (i.e. `S'` stays in `free`, but its energy gets an extra `π_goal·(S'−goal)²` term pulling it), leave `A` free with no clamp term at all. Read off the settled `A`.
4. A fifth, deliberately broken config on the classification/generation subgraph: hard-clamp `X` to one class's pattern **and** hard-clamp `L` to a *different, incompatible* class, both at once. Free only `Z`. Plot or print the energy trace and show it plateaus well above the near-zero level the three satisfiable configs reach.

**Deliverable:** the script, plus a short (5–10 line) printed or written summary of what settled where in each of the 5 runs, including the energy trajectories.

**Rubric**

| Band | Criteria |
|---|---|
| Strong | One settle function reused across all configs (not five copy-pasted loops); all three L/Z/X configs converge to near-zero energy with correct qualitative results (classification recovers the clamped class, generation reproduces the class pattern, reconstruction fills in the missing half reasonably); goal-directed config correctly frees only `A` and `S'` while `S` never changes; over-constrained config's energy visibly plateaus above the satisfiable configs' floor and the learner states why (two hard clamps making incompatible demands on the same latent path).      |
| Adequate | Configs work but with duplicated per-config code instead of one settle function; OR one of the three L/Z/X results is only roughly right; OR the over-constrained config is shown but the explanation for the plateau is missing or wrong.          |
| Not yet | Clamped nodes are updated by the gradient step anyway (clamping not actually enforced as a boundary condition); or the "goal-directed" config accidentally also clamps `A` or lets `S` move; or the over-constrained config also converges to ~0 (meaning the two clamps weren't actually made incompatible).      |

**Grader key** (teacher AI only — reference numbers from one working implementation; exact figures will differ by init/seed, so grade on *pattern*, not exact match)

- Classification: energy fell from **1.44 → 0.002** over 300 steps; settled label vector **[0.01, −0.04, 1.00]**, correctly arg-maxing to the clamped class.
- Generation: energy fell from **1.71 → 0.0006**; generated `X` matched the class prototype to **MSE 0.0007**.
- Reconstruction (first 3 of 6 dims clamped, last 3 free): energy fell from **1.45 → 0.011** — note this floor is *higher* than classification/generation's, because only partial evidence is available; MSE on the reconstructed half was **0.072**, an order of magnitude worse than the full-evidence configs. Inferred label matched the true class in the reference run.
- Over-constrained (`X` clamped to class 0's pattern, `L` clamped to class 1, only `Z` free): energy dropped fast then **plateaued at 2.38** and stayed flat for the remainder of the run — roughly 1000–2000× the floor the satisfiable configs reached. This is the numerical signature of "no settled solution": the single free node (`Z`) cannot simultaneously make both hard clamps consistent, so residual error is stuck rather than decaying.
- Goal-directed: with current state clamped to `[0, 0]` and desired next state soft-clamped to `[0.05, 1.0]`, the settled action was **A ≈ 4.86**, settled `S'` ≈ `[0.04, 0.91]` — close to but not exactly the goal, and energy fell from **5.01 → 0.22**, a nonzero floor. That nonzero floor is not a bug — it is Piece 1's finite-π residual showing up empirically: the goal pull has finite precision, so `S'` settles to a compromise between "consistent with the dynamics prediction" and "at the goal," exactly as the algebra in Piece 1 predicts. Point this connection out if the learner doesn't make it themselves.

**Teacher constraints**
- Hint 1: "You should be able to call the *same* function for all three L/Z/X configs, passing a different `free` set each time. If you're writing separate loops, factor that out first."
- Hint 2: "For the goal-directed config, check which nodes literally never change value across iterations — that's your clamp list. `S` should be in that list; `A` and `S'` should not."
- Hint 3: "For the over-constrained config, don't chase a bug if the energy won't reach zero — check whether that's the correct behaviour first, by comparing to the satisfiable configs' floor."
- Never: hand over a working settle function or the dynamics-prediction formula. Never tell the learner what number their over-constrained energy "should" plateau at before they've run it — ask them to compare it to their own satisfiable-config floor.

## Piece 3 — Guided reading: Friston, Daunizeau & Kiebel (2009), *Reinforcement Learning or Active Inference?*

**Type:** guided reading · **Time:** ~45–60 min

**Learning goals**
- Locate, in a primary source, the distinction between resolving prediction error by changing beliefs (perception) versus changing the world via effectors (action).
- Identify the specific move that makes a desired/goal state a "frozen prior" — a prior that is not updated by incoming evidence.
- Connect that move to the CartPole clamp pattern already used in the project.

**Task**

Read the paper (`papers/C5_friston_2009_active_inference.pdf`) with these questions in hand — answer each with a page/section reference and a 1–3 sentence answer in your own words:

1. The paper treats perception and action as two different ways of doing the same thing (minimizing free energy / prediction error). Find where it states this explicitly. What changes in the perception case, and what changes in the action case?
2. Find where the paper introduces a prior expectation about a desired or preferred state (a goal), and describe how that prior is treated differently from an ordinary belief about the current hidden state — specifically, is it something the model updates in light of sensory evidence, or something held fixed regardless of evidence?
3. Given your answers to 1 and 2: in the paper's scheme, if the current sensory state is *also* being fed in as data (not free to change), which variable is left with no other way to reduce error except by driving action? Why can't the model instead "give up" on the goal and revise its prior about what it wants?
4. One paragraph, in your own words: map the paper's terms onto this project's vocabulary. What does the paper call the thing this course calls a "hard clamp on current sensory state"? What does it call the "soft clamp on desired future state"? What does it call the free node this course calls "ACTION"?

**Deliverable:** four short written answers (a few sentences each), each with a specific reference into the paper (section name, or a paraphrased quote you can point back to).

**Rubric**

| Band | Criteria |
|---|---|
| Strong | All four answers cite a specific, correct location/passage; Q3's answer correctly names the *action* variable (not a belief variable) as the one left free, and gives the actual reason (the current-state prior is pinned to real sensory data, so revising the current-state belief can't remove the error — only changing the state itself, via action, can) rather than a restated definition. Q4 maps to the paper's own terms without asserting the paper uses the project's clamp vocabulary verbatim.        |
| Adequate | Three of four answers correctly located and reasoned; Q3 gets the right variable (action) but the "why" is hand-wavy ("because it's the only thing left") rather than grounded in the asymmetry between fixed sensory evidence and revisable belief.          |
| Not yet | Answers are generic active-inference summary without page/section grounding, or Q3 names a belief/perceptual variable as the one that resolves the error (missing the point that the paper's whole argument is that action, not belief revision, closes that particular loop).       |

**Grader key** (teacher AI only)

1. The paper frames both perception and action as free-energy minimization but along different variables: perception minimizes free energy with respect to internal/representational states (updating beliefs to better predict sensory input); action minimizes the *same* free energy with respect to the states of the world reachable through effectors (changing sensory input itself so it matches predictions), typically discussed around the paper's treatment of "active inference" and reflex-arc-like descending predictions. Accept any correctly-located passage distinguishing "change the model" (perception) from "change the sensed world" (action).
2. The paper casts goals/preferences as prior expectations over future or terminal states that are *not* updated by sensory evidence — they act as fixed attractors the system tries to fulfil rather than beliefs the system revises when data disagrees with them. This is the "frozen prior": immune to the update step that ordinary hidden-state beliefs get.
3. The action variable. The current sensory state is clamped to the actual data (it is what is, not what is believed), and the goal-state prior is held fixed by construction (it is not a target of belief updating). With both of those pinned, the only remaining route to reduce the free energy / prediction error between "what is" and "what is desired" is to change the world — i.e., to act — because neither of the two things being compared is allowed to move to meet the other.
4. Acceptable mappings: current-sensory-state hard clamp ≈ the paper's sensory input / observed outcome fed into the recognition model; desired-future-state soft clamp ≈ the paper's prior over future/goal states (sometimes framed via a prior policy or preference distribution biased toward the goal); free ACTION node ≈ the paper's action variable driven by the free-energy gradient with respect to action (often tied to descending proprioceptive predictions / reflex arcs in its exposition). Do not require exact paper terminology to match the project's words one-to-one — the map only needs to be recognizably correct, since the project's vocabulary ("clamp") is not this paper's own word for it.

**Teacher constraints**
- Hint 1: "Skim for where the paper talks about 'two ways to minimize free energy' or contrasts perception and action directly — that's where Q1's answer lives."
- Hint 2: "For Q2, look for where a desired or preferred outcome is introduced as part of the generative model, and ask: does anything in the text say this gets updated by data, the way an ordinary belief does?"
- Hint 3: "For Q3, don't answer with a definition of active inference — answer the specific question: given both endpoints of the comparison are pinned, what's left that can move?"
- Never: paraphrase the paper's argument for the learner or supply the section reference outright — direct them to the right neighbourhood ("look near the perception/action distinction," "look near where preferences are introduced") and let them find the exact passage.

## Piece 4 — Written defence

**Type:** written defence · **Time:** ~45 min · **Length:** 300–600 words

**Learning goals**
- Explain the CartPole clamp pattern in this project's own terms, from the ground up, without reciting a memorized list.
- Articulate the asymmetry (fixed current state + frozen goal prior + free action) as the mechanism that forces resolution via behaviour rather than belief revision.
- Distinguish two distinct failure modes of clamping and give one concrete example of each.

**Task**

Write a 300–600 word defence answering all of the following in one coherent piece of prose (not a Q&A list):

1. For the CartPole online rollout (`online_rollout.py`, `train_cartpole.py`): which nodes are clamped, which are free, and which node's settled value is read out as the answer? State this, then explain *why* each of those three roles is assigned the way it is — not just what the roles are.
2. Explain, referencing Piece 1's derivation, why the frozen-prior/goal-clamp setup forces the network to resolve error by acting rather than by revising its belief about the goal. Your answer should make clear this isn't a rule bolted onto the architecture — it follows from which nodes are allowed to move.
3. Give one concrete over-constrained clamp scenario (in this project's domain or in the MNIST classification/generation domain) and describe what the network does instead of settling to a low-energy solution.
4. Give one concrete scenario where a clamp is satisfied by hallucination — i.e., the free nodes do settle to a low-energy state, but that state is not a correct or useful answer, only one that happens to be locally consistent. Explain what distinguishes this from the over-constrained case in (3): here the network *does* settle; the failure is in *what* it settled to, not in the fact that it settled.

**Deliverable:** 300–600 words of prose.

**Rubric**

| Band | Criteria |
|---|---|
| Strong | Correctly identifies the CartPole clamp pattern (sensor observations hard-clamped, desired next state soft-clamped, ACTION free and read out) and explains the *why* for each role, not just the *what*. Explicitly ties the "acts rather than revises belief" argument back to which nodes are free/clamped rather than asserting it. Gives a genuinely over-constrained example (two hard clamps in conflict, no free node can reconcile them) distinct from a hallucination example (free nodes settle to a self-consistent but wrong/degenerate state, e.g. a generation config settling to a blurry average-of-classes image, or a reconstruction config completing a corrupted digit as a different, wrong, but visually plausible digit). Clearly states settling-vs-not-settling as the distinguishing line between the two failure modes.        |
| Adequate | Gets the CartPole roles right but the "why" is thin (restates the roles instead of explaining the forcing mechanism); failure-mode examples are plausible but the distinction between them (settles-vs-doesn't) is not stated explicitly.          |
| Not yet | Misassigns a CartPole role (e.g. treats the observation as free, or the action as clamped); conflates the two failure modes, or gives the same example for both; describes "acting instead of believing" as an arbitrary rule rather than deriving it from the fixed/free assignment.      |

**Grader key** (teacher AI only)

1. Observations are hard-clamped (real sensor data, not negotiable). The desired next state is soft-clamped (a goal the network is pulled toward but which can, at finite precision, be traded off against other pressure). ACTION is free and is what gets read out. Why: the sensor reading is ground truth by construction — there is nothing to infer about it, so clamping it hard both reflects that and stops the network from "explaining away" real data. The goal is soft rather than hard because it must be tradeable against dynamics-consistency and other constraints (an unreachable goal shouldn't force nonsense) — see Piece 1's finite-π residual. ACTION is left free because it is the only node with no external ground truth *and* no fixed target: it is exactly the slot whose value the network is being asked to compute.
2. With current state pinned to real data and the goal pinned as a non-revisable prior, the only free variable that can move is the one PC uses to reduce the remaining error — mechanically identical to Piece 1's `x*` equation, but now with two "clamp-like" terms (sensory precision → ∞, goal precision finite-but-large) and one genuinely free node (action) that absorbs whatever gradient remains. Nothing needs to be added to the architecture to get "act, don't rationalize" — it falls out of which nodes are allowed to have a gradient step applied at all.
3. Example: clamping an MNIST image to a 7 and the label to "3" simultaneously (or, in the CartPole domain, clamping the current state to one reading while soft-clamping an already-reached, contradictory "current" state as if it were still to be achieved). Nothing settles to low energy; the one remaining free node (a shared latent) is pulled in two directions and the energy plateaus at a value set by how incompatible the two clamps are, as shown numerically in Piece 2.
4. Example: a generation config with a label clamped but a weak or under-trained decoder settles the free image node into a blurry, generic blob that isn't a clean digit for that class but is self-consistent (low energy) given the model's (bad) decoder — or a reconstruction config that completes a corrupted "8" as a "0" because "0" was locally lower-energy given the visible top half, even though the true digit was "8". The distinguishing line: in (3) the energy never gets low — there is visibly no answer; in (4) the energy gets low — there is an answer, and it's confidently wrong. Non-settling is a search/consistency failure; hallucination is a model-capacity/coverage failure.

**Teacher constraints**
- Hint 1: "State the three CartPole roles first, in one sentence each, before trying to explain the 'why' — separate the what from the why."
- Hint 2: "For the forcing argument, go back to Piece 1's equation — what does it say happens to a node when it has no gradient path left except through one variable?"
- Hint 3: "For the two failure-mode examples, ask of each one: did the energy actually go down to near its floor, or not? That answer tells you which failure mode you're describing."
- Never: draft any sentence of the defence for the learner, or supply the hallucination/over-constrained examples verbatim — offer the settles-vs-doesn't-settle distinction as a diagnostic question, not the example itself.

## Completion bar

The learner is done with C5 when, unaided (no notes, no re-reading Piece 1/2 solutions):
- They can redraw the four-task clamp table (classification / generation / reconstruction / goal-directed) from the fixed-vs-free principle alone, including the reconstruction-vs-generation contrast.
- They can redraw the CartPole clamp diagram (observation hard-clamped, desired next state soft-clamped, ACTION free and read out) and explain *why* each role is assigned that way, not just recite it.
- They can state the soft-clamp energy term, solve for `x*`, and explain in one sentence why π→∞ gives the hard clamp as a special case rather than a separate rule.
- They can distinguish, with an example each, an over-constrained clamp (doesn't settle) from a hallucinated one (settles, but wrong).

If any of the four fails, route back to the relevant piece above rather than re-teaching from scratch — Piece 1 for the algebra and table, Piece 2 or 4 for the failure-mode distinction, Piece 3/4 for the CartPole "why."
