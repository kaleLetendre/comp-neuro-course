## Piece 1 — Replay compression and interference arithmetic

**Type:** derivation · **Time:** ~35 min

**Learning goals**
- Convert a stated replay compression factor into concrete event durations and rest-period replay counts.
- Separate "how much replay capacity exists" from "how replay changes interference," using the same numbers.
- Derive, from a minimal delta-rule model, how fast a single-stream (blocked) update forgets a prior target, and how a small interleaving fraction slows that down — with a closed-form relationship, not a hand wave.

**Task**

*Part A — compression and rest-period capacity.*
1. A rat runs a linear-track arm in T_behavior = 6.0 s, laying down a place-cell sequence. Hippocampal SWR replay compresses this by C = 20×. Compute the replay event duration T_replay.
2. In a 10-minute (600 s) post-run rest period, SWR events occur at an average rate of one every 2 s (0.5 Hz, typical for quiet wake / early sleep shortly after behavior), each carrying one replay of that sequence. Compute how many replay events fit in the rest period, and express that as a ratio to the single live run (which happened exactly once).
3. In one sentence, state what that ratio implies about how many times a downstream (cortical) learner effectively "sees" the episode if it learns only from replay, not from the live event.

*Part B — interference arithmetic with a delta rule.*
Model a scalar weight learning online: w_{t+1} = w_t + η(target_t − w_t), η = 0.1, w_0 = 0.
4. Phase 1 (task A only, 50 steps): target_t = w_A* = 2.0 for t = 1..50. Using the closed form w_t = w_A*(1 − (1−η)^t), compute w_50.
5. Phase 2, **blocked** condition (matches Step 2b's single correlated stream — no task-A samples at all once the switch happens): target = w_B* = −3.0 for the next 50 steps. Using w_t = w_B* + (w_50 − w_B*)(1−η)^t (t counted from the switch): (a) compute w after 50 more steps; (b) find the number of steps t after the switch at which the task-A error |w_t − w_A*| first falls to half its maximum possible value (|w_A* − w_B*| / 2 = 2.5, i.e. w_t = −0.5).
6. Phase 2, **interleaved** condition: each step draws target = w_B* with probability 0.8 and target = w_A* with probability 0.2 (a 20% replay ratio). Compute the expected target, the steady-state expected weight (t → ∞, where expected update = 0), and the resulting steady-state task-A error. Compare it numerically to the blocked condition's steady-state error (r = 0).

**Deliverable:** a half-page to one-page writeup with all 6 numeric answers and working shown, plus 2-3 sentences connecting question 6's result to why a modest interleaving fraction — not a huge buffer — already recovers most of the benefit.

**Rubric**

| Band | Criteria |
|---|---|
| Strong | All 6 numeric answers correct within rounding; the general formula in Q6 (steady-state error = (1−r)·\|w_B*−w_A*\|) is stated or clearly implied; the closing sentences correctly identify that error scales linearly (not steeply) with replay fraction r. |
| Adequate | Part A fully correct; Part B has the right method but an arithmetic slip in one of Q4-6, or the closing interpretation is present but vague. |
| Not yet | Compression arithmetic wrong (e.g. multiplying by C instead of dividing), or the delta-rule recursion is set up backwards (target and current value swapped), or Q6 treated as requiring simulation rather than the fixed-point argument. |

**Grader key** (teacher AI only)

1. T_replay = 6.0 / 20 = **0.3 s (300 ms)**.
2. Number of events = 600 / 2 = **300 events**; ratio to the single live run = **300 : 1**.
3. Expected content: if a downstream learner only learns from replay, it sees on the order of ~300 repetitions of an episode that occurred live exactly once — replay inflates a single sparse experience into a large effective training signal, which is what lets a fast one-shot hippocampal trace teach a slow interleaved cortical store without re-living the event.
4. w_50 = 2.0(1 − 0.9^50). 0.9^50 ≈ 0.00515 → w_50 ≈ 2.0 × 0.99485 ≈ **1.99**.
5. (a) w_100 = −3.0 + (1.9897 − (−3.0)) × 0.9^50 = −3.0 + 4.9897 × 0.00515 ≈ **−2.97**. Task-A error ≈ |−2.97 − 2.0| = **4.97** — within 50 steps the network has moved ~99.5% of the way to task B's value; effectively total forgetting.
   (b) Solve −3.0 + 4.9897 × 0.9^t = −0.5 → 0.9^t ≈ 0.5010 → t = ln(0.5010)/ln(0.9) ≈ **6.6, i.e. 7 steps**. Half-forgotten within 7 update steps of the context switch.
6. Expected target = 0.8(−3.0) + 0.2(2.0) = **−2.0**. Fixed point (E[Δw] = 0) gives w_∞ = **−2.0**. Steady-state task-A error = |−2.0 − 2.0| = **4.0**, vs. **5.0** in the fully blocked limit (r = 0, w_∞ → w_B* = −3.0). General relationship: steady-state error = (1 − r)·|w_B* − w_A*|; at r = 0.2, (1−0.2)×5.0 = 4.0, consistent. The point the closing sentences should reach: doubling r from 0 to 0.2 already buys a 20% reduction in asymptotic error — the relationship is linear in r, so a cheap, small interleave fraction is not a token gesture, it's proportionally exactly as good as its size suggests.

**Teacher constraints**
- Hint 1: if stuck on 5(b), point at isolating 0.9^t and taking logs of both sides — do not do the log arithmetic for them.
- Hint 2: if stuck on 6, point at the fixed-point condition "expected update = 0" rather than asking them to unroll the recursion by hand.
- Hint 3: if the general formula in 6 isn't emerging, ask them to re-derive it symbolically with r as a variable instead of plugging in 0.2 directly.
- Never: never state the final numeric answer to any sub-question before you has submitted an attempt; never supply the general formula (1−r)·|w_B*−w_A*| unprompted.

## Piece 2 — Catastrophic forgetting and the cheapest fix

**Type:** simulation · **Time:** ~70 min

**Learning goals**
- Build a minimal two-task forgetting setup in plain PyTorch, using only SGD (matching Step 2b's optimizer constraint).
- Observe catastrophic forgetting as a number, not a claim.
- Implement the cheapest possible replay buffer and show numerically that it mitigates forgetting.
- Articulate the difference between "forgetting" (weights moved by new gradients) and "state-dependent output" (same weights, different carried-forward input/state) — the distinction the Step 2b attractor test already raised.

**Task**

Build one self-contained script (<100 lines, numpy/PyTorch only, no downloads):

1. Two synthetic supervised tasks over the same input distribution x ~ N(0, I_8): task A target y_A = w_A·x + 0.3·sin(v_A·x), task B target y_B = w_B·x + 0.3·sin(v_B·x), where (w_A, v_A) and (w_B, v_B) are two different fixed random vectors (seeded). Generate 2000 training samples and 500 held-out test samples per task.
2. A small MLP: 8 → 32 (tanh) → 1. A single `torch.optim.SGD` instance with one fixed learning rate for the whole experiment — no Adam, no schedule (this mirrors Step 2b's "Adam state carried over blows up, SGD only" constraint).
3. Phase 1: train on task-A batches only (batch size 32) for 300 steps. Save the model state and record task-A test MSE — this is the baseline.
4. Phase 2, **blocked**: reload the phase-1 checkpoint fresh, train exclusively on task-B batches for 300 more steps with the same optimizer settings. Record task-A and task-B test MSE.
5. Phase 2, **replay**: reload the same phase-1 checkpoint again. Before any task-B training, freeze a buffer of 64 task-A samples. Train on task-B batches for 300 steps, but on every step replace ~20% of the minibatch (6 of 32 examples) with examples drawn (with replacement) from that frozen buffer. Record task-A and task-B test MSE.
6. Print a 3×2 table: {baseline, blocked, replay} × {task-A MSE, task-B MSE}.

**Deliverable:** the script, plus 4-6 sentences covering: (a) which condition shows forgetting and roughly by what factor; (b) whether replay recovers task-A performance and what it costs task-B performance; (c) one sentence distinguishing this forgetting (a weight change driven by new gradients) from the attractor test's state-dependence (same weights, different carried-forward state producing different settled output).

**Rubric**

| Band | Criteria |
|---|---|
| Strong | Script runs end-to-end and produces baseline < replay < blocked ordering on task-A MSE; write-up correctly attributes the ordering to interference vs. buffer-mitigated interference, and (c) draws the forgetting/state-dependence distinction precisely (weight change vs. no weight change). |
| Adequate | Ordering holds but write-up (c) is vague or conflates the two phenomena; or buffer size/interleave ratio was changed from spec without noting why, but the comparison is still fair (same checkpoint reloaded for both phase-2 branches). |
| Not yet | Blocked and replay conditions don't start from the same phase-1 checkpoint (confounds the comparison); or no held-out test set (train-set MSE only); or buffer captured after task-B training has already started; or forgetting doesn't appear at all and the script wasn't debugged against the checklist in Hint 2. |

**Grader key** (teacher AI only)

Numbers are seed-dependent; check the *pattern*, not exact values.
- Baseline task-A MSE should be clearly low relative to the target's own variance (the MLP has capacity to fit this).
- Blocked condition: task-A MSE should rise substantially — commonly 5-50× the baseline, often approaching the MSE of a naive mean-predictor, since 300 steps of task-B-only SGD with no task-A signal should overwrite most of the task-A fit. Task-B MSE in this condition should now be low.
- Replay condition: task-A MSE should sit clearly between baseline and blocked — expect roughly within 2-5× of baseline rather than 10-50×; task-B MSE should still drop close to its own low value, with a modest increase relative to the blocked condition's task-B MSE (interleave ratio is only 20%, so task-B still dominates the stream).
- Pass condition: baseline < replay < blocked on task-A MSE. If you reports replay ≈ blocked (no visible improvement), the likely bugs are: buffer captured after task-B training started (so it's already contaminated), buffer being subjected to task-B's optimizer step too (i.e. not actually held fixed, just relabeled), interleave fraction too small to show an effect at this step count, or the two phase-2 runs not both starting from the identical phase-1 checkpoint.

**Teacher constraints**
- Hint 1: if blocked shows no forgetting, ask "are the two target functions different enough, and are both phase-2 branches loading the same saved phase-1 checkpoint rather than continuing from wherever the previous branch left off?"
- Hint 2: if replay shows no improvement over blocked, ask them to print what fraction of each minibatch actually comes from the frozen buffer, and confirm exactly when the buffer was captured.
- Hint 3: state the expected ordering (baseline < replay < blocked) without giving numeric magnitudes.
- Never: never write the model class, training loop, or buffer-sampling code for you; never supply exact MSE thresholds beyond confirming the ordering is right.

## Piece 3 — Guided reading: Ólafsdóttir et al. 2018

**Type:** guided reading · **Time:** ~40 min

**Learning goals**
- Extract specific, prose-only claims about replay's temporal structure and behavioral-state dependence.
- Connect the paper's systems-consolidation framing to the CLS argument already covered in this lesson.
- Identify precisely what preplay evidence does and does not establish about replay's origin.
- Locate causal (manipulation-based), not merely correlational, evidence for replay's function, and articulate why that distinction matters.

**Task**

Read `papers/B5_olafsdottir_2018_replay_memory_planning.txt` once in full (no figures are available in this text — all questions are answerable from prose). Answer the following in your own words, 2-5 sentences each, naming the section/paragraph each answer is drawn from:

1. What temporal compression factor (or range) does the review report for hippocampal SWR replay relative to the original behavior, and in which behavioral states does the review say this replay predominantly occurs (relative to active locomotion)?
2. The review situates replay within systems consolidation. In your own words, what role does it propose replay plays in moving information from hippocampus to neocortex — and how does that connect to the CLS argument (one network cannot be both a fast one-shot learner and interference-free)?
3. The review distinguishes forward and reverse replay sequences. Summarize the functional or contextual difference it associates with each (e.g. reward-related/retrospective vs. prospective/planning).
4. Find the review's discussion of "preplay" — replay of a trajectory the animal has not yet physically traversed. What does the existence of preplay rule out as a *complete* explanation of where replay content comes from, and what alternative function does it support instead?
5. The review discusses experiments that disrupt SWRs (e.g. closed-loop stimulation timed to ripples) rather than just recording them. What behavioral/memory consequence is reported when SWRs are selectively disrupted, and why does the review treat this kind of evidence as stronger than correlational place-cell recordings alone?
6. Find one passage connecting replay to spatial planning or decision-making (not just passive consolidation). What does it suggest about replay's function beyond rehearsing already-lived experience?
7. (Synthesis — not from the paper's text alone.) Based on what you've read about how a replay event is structured — a compressed, temporally ordered place-cell sequence drawn from very recent experience — contrast this with how a single sample is typically drawn from a standard RL experience-replay buffer (i.i.d./uniform sampling over a large stored history). Name one concrete structural difference: ordering, compression, or source of samples.

**Deliverable:** numbered answers (2-5 sentences each), each citing the section/heading it was drawn from.

**Rubric**

| Band | Criteria |
|---|---|
| Strong | All 7 answered with correct content traceable to the actual text (verified by the grader against the source), each with a real section citation; Q7 names one specific, correctly-reasoned structural difference rather than a vague "they're different." |
| Adequate | 5-6 of 7 correct and cited; one answer conflates two concepts (e.g. preplay with reverse replay) or Q7 is directionally right but imprecise. |
| Not yet | Citations are missing or don't match what's actually in that section when checked; more than 2 answers wrong or fabricated (e.g. inventing a specific number not in the text). |

**Grader key** (teacher AI only — verify each against the actual paper text before crediting; do not accept a citation that doesn't match the cited section)

1. Expect a compression factor in the range typically reported for SWR replay in this literature (commonly cited as roughly 6-20×, sometimes stated as a specific value in the text — accept whatever figure the paper itself states, don't penalize for not matching an external number). Behavioral states: quiet wakefulness/rest and slow-wave sleep — explicitly *not* during active running/locomotion.
2. Replay proposed as an offline training signal moving fast-formed hippocampal episodic traces into slower, interleaved neocortical storage. CLS link: a single network can't be both highly plastic (fast, one-shot learning) and stable/interference-free at the same time, so the two functions are split across two systems (hippocampus fast/sparse, cortex slow/interleaved), with replay as the transfer mechanism between them.
3. Reverse replay classically tied to reward/outcome evaluation — occurring preferentially just after reaching a reward, replaying the just-completed path backward. Forward replay tied to prospective processing — sequences running in the direction of upcoming or planned trajectories. Credit any answer matching this general shape as stated in the paper's own framing.
4. Preplay rules out "replay content is purely reactivation of a physically lived, previously encoded sensorimotor trace" — since the trajectory was never traveled, it cannot be simple rehearsal of stored experience. It supports a generative or planning-like function: sampling possible paths from a learned cognitive map, consistent with a role in evaluating options rather than only consolidating the past.
5. Reported consequence: impaired subsequent memory performance or learning when SWRs are selectively disrupted (e.g. via closed-loop stimulation). This is treated as stronger evidence than correlational recording because it is a causal manipulation — it shows replay is *necessary* for the memory effect, not merely co-occurring with it.
6. Any passage tying replay/preplay to route selection, shortcut discovery, or evaluating reward-relevant paths — supporting a function beyond passive rehearsal, into simulating or evaluating candidate futures.
7. Any one clearly and correctly stated structural difference is sufficient, e.g.: replay preserves (compressed) temporal order matching an actual trajectory, whereas RL buffer sampling is typically i.i.d./uniform with no ordering; or replay draws from a small, recent window of lived experience, whereas an RL buffer holds and uniformly samples a much larger, older history; or replay's temporal compression (speed-up relative to original experience) has no analogue in standard RL replay, which replays a transition at its original single-step granularity.

**Teacher constraints**
- Hint 1: if you can't find the compression figure, point them to the introductory/background paragraphs describing ripple properties — do not say "it's not in a table" more than once, and do not give the number.
- Hint 2: if Q4 conflates preplay with reverse replay, ask them to re-read the specific paragraph that defines preplay before re-answering.
- Hint 3: if Q7 is vague ("they're different"), ask for exactly one of the three named properties (ordering, compression, source) as the acceptance criterion itself specifies.
- Never: never summarize a section's argument in place of you reading it; never state the compression number or the preplay conclusion before you has attempted an answer; never credit a citation that doesn't actually match the paper's text at that heading.

## Piece 4 — Written defense: does Step 2b need replay?

**Type:** written defense · **Time:** ~40 min · 300-600 words

**Learning goals**
- Convert the quantitative and CLS/replay understanding above into a scoped, falsifiable engineering proposal.
- Reason about what "replay" means for a network that carries persistent activity state across timesteps, rather than resetting per sample.
- Propose an experiment that can distinguish "replay helped" from "we got a good seed or learning rate."

**Task**

Write 300-600 words addressing, specifically for Step 2b's online rollout (single correlated stream, no buffer, no interleaving, SGD-only because Adam state carried over from training blows up):

(a) Should Step 2b add a replay mechanism, or is the instability seen in the online rollout better explained by something else (learning rate, optimizer-state carryover, etc.)? Take an explicit stance.

(b) If yes: sketch the cheapest version — buffer size (order of magnitude is fine), interleave ratio, and, critically, what gets *stored* given the network carries persistent activity state across timesteps. Raw (observation, target) pairs replayed later land in whatever state the network happens to be carrying at that later moment, not the state they originally occurred in — say what you'd snapshot instead (or argue explicitly why raw pairs are good enough despite this).

(c) Name one concrete experiment, using the project's existing tooling (`headless_rollout` / `online_rollout` — no code required, just describe the comparison), that would distinguish "the buffer is doing something" from "this run just had a favorable seed or learning rate."

**Deliverable:** one 300-600 word document.

**Rubric**

| Band | Criteria |
|---|---|
| Strong | Clear stance with reasoning tied to the CLS/interference arguments above; buffer sketch gives a concrete order-of-magnitude size and interleave ratio; explicitly engages with the persistent-state storage problem (not just "store transitions"); experiment description isolates the buffer as the causal variable (matched seeds/other hyperparameters, a repeatable probe). |
| Adequate | Stance and buffer sketch present but the persistent-state issue is only gestured at, not resolved; experiment description compares conditions but doesn't control for seed/hyperparameters, so it wouldn't actually isolate the buffer's effect. |
| Not yet | No clear stance ("it depends," no commitment); buffer sketch is generic ML boilerplate with no engagement with Step 2b's specific persistent-state constraint; no proposed experiment, or one that couldn't in principle distinguish replay's effect from noise. |

**Grader key** (teacher AI only — model answer sketch, not a required exact match)

- Stance: yes, add a minimal replay mechanism. The online rollout's single-pass correlated stream is exactly the CLS fast-learner-without-interleaving scenario from this lesson. The attractor test already shows output is state-dependent; without any interleaving, there is currently no way to tell "state-dependence" apart from "the weights have actually drifted" (forgetting) — which is itself the reason a diagnostic/fix is needed, not a reason to dismiss the idea.
- Cheapest version: a small fixed-size buffer, order 10¹-10² (e.g. 32-128 entries), FIFO or reservoir-sampled, populated by snapshots taken periodically (e.g. every K steps) during the rollout. Interleave ratio low, e.g. 10-25% of updates drawn from the buffer vs. the live stream (matches Piece 1's derivation that even a 20% interleave fraction roughly halves eventual drift). On persistent state: storing only the raw (observation, target) pair is insufficient, because replaying it later re-injects it into whatever state the network is carrying *then*, not the state it originally arose in. The snapshot should include the network's persistent activity/hidden state at capture time (so replay can restore that context before applying the sample), or store a short sub-trajectory window rather than a single decorrelated transition, so the replayed update happens in a context resembling the original one.
- Experiment: run matched-seed online rollouts with vs. without the buffer over a long horizon, holding learning rate and all other hyperparameters fixed. Periodically re-probe both conditions on a fixed early-episode condition (e.g. the same angle-hold state used in the attractor test). If the no-buffer condition's early-probe performance degrades over time while the buffer condition's stays flat — with comparable current/live performance in both — that is evidence the buffer is fixing forgetting specifically, not just producing a generically better run (a lucky seed or learning rate difference would instead show up as different live performance, not a growing gap between early-probe and live performance over time).

**Teacher constraints**
- Hint 1: if the stance is wishy-washy, ask them to reread Piece 1 Q6 (the numeric effect of interleaving) and commit to a position based on it.
- Hint 2: if (b) doesn't engage with persistent state, ask directly: "if you replay this stored sample later, what context does the network apply it in — is that the same context it came from?"
- Hint 3: if (c) doesn't control for seed, ask what would happen to their proposed comparison if one run simply had a better random seed than the other.
- Never: never supply the buffer size, interleave ratio, or storage design before you has produced their own; never tell them what to conclude about whether Step 2b needs replay.
